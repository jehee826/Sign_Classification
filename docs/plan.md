# 수화 이미지 분류 상세 계획

갱신일: 2026-11-18

## 1. 목표와 범위

팀원이 직접 촬영한 한글 지문자 자음 14종을 분류한다. 사진과 비교용 분할은 팀 전체가 공유하고 각자 모델을 개발한다. 최종 선정 코드와 결과는 팀원 모두 설명할 수 있어야 한다.

클래스 번호 0~13은 `ㄱ, ㄴ, ㄷ, ㄹ, ㅁ, ㅂ, ㅅ, ㅇ, ㅈ, ㅊ, ㅋ, ㅌ, ㅍ, ㅎ` 순서다. 클래스 폴더는 `c00`~`c13`이다. 쌍자음과 모음은 제외한다.

기본 라이브러리의 이미지 입출력·배열 연산·보간·그래프 기능은 활용한다. 전처리 판단 규칙, CNN 구성, 학습·평가 흐름은 직접 작성한다. 사전학습 가중치, 완성 분류 모델, 자동 손 검출·키포인트·배경 제거 파이프라인은 사용하지 않는다. 웹·DB·서비스 인프라는 범위에 없다.

## 2. 코드 네 파일의 책임

네 구현 파일은 `src/`에 배치한다. 공통 전처리는 `src/data_processing.py`에서 학습과 추론에 제공한다. `requirements.txt`는 저장소 루트의 별도 의존성 목록이며 구현 파일 네 개에 포함하지 않는다.

데이터·학습 결과·추론 가중치는 실행 폴더와 무관하게 저장소 루트의 `data/`, `runs/`, `best.pt`를 사용한다. 루트에서 `python src/train.py`, `python src/predict.py --input test_images/ --output predict_팀번호.csv`로 실행한다. `--input`·`--output`의 상대 경로는 현재 실행 폴더 기준이다.

제출물도 `src/` 구조를 유지한다. 과제 명령은 `src/` 안에서 `python train.py`, `python predict.py --input ../test_images/ --output ../predict_팀번호.csv`로 실행하면 루트의 시험 이미지를 읽고 루트에 결과를 만든다. 원문의 `--input test_images/ --output predict_팀번호.csv`를 그대로 쓰려면 해당 입출력은 `src/` 기준이다. 파일을 루트로 평탄화하지 않는다.

### data_processing.py: 데이터 처리

- 사진 목록·메타데이터·분할 검사와 사용자 정의 Dataset을 담당한다.
- EXIF 방향 보정, RGB 변환, 비율 유지 리사이즈·패딩, 텐서 변환을 공통 함수로 제공한다.
- 학습용 증강은 공통 결정적 전처리와 구분하고, 적용 조건·좌표·난수를 명시한다.
- `train.py`와 `predict.py`가 같은 전처리를 호출한다. 추론은 학습용 메타데이터나 분할 파일이 없어도 동작해야 한다.

### model.py: 모델 전체 구조

- CNN 클래스와 순전파만 정의한다. 데이터 읽기·학습·가중치 다운로드를 하지 않는다.
- 입력 `[B,3,128,128]`에서 출력 `[B,14]` 로짓을 반환한다.

### train.py: 학습 코드

- 데이터와 분할 확인, 난수 설정, DataLoader, 모델 생성, 학습·평가·증강 비교를 담당한다.
- 조건별 가중치·epoch 로그와 최종 혼동행렬·비교 결과를 저장한다.
- 루트의 `python src/train.py` 또는 `src/` 안의 `python train.py`로 무작위 초기화부터 전체 실험을 다시 시작한다.

### predict.py: 추론 코드

- `--input`, `--output` 인자를 받고 가중치와 입력 폴더를 검사한다.
- 공통 전처리와 모델 정의를 이용해 예측하고 `filename,pred` CSV를 저장한다.
- 학습·증강·가중치 재선정은 하지 않는다.

## 3. P01: 데이터 확인과 공통 분할

- [ ] 팀원 1인당 자음별 30장 이상, 총 420장 이상인지 확인한다.
- [ ] JPG 긴 변 640px 이상, 배경 3종 이상, 조명 2종 이상, 다양한 각도·스케일을 포함하는지 확인한다. 손 크기는 화면 높이 약 3/4·1/2·1/3을 포함한다.
- [ ] 흐린 사진·틀린 손 모양·연사 복제·외부 사진을 제외하고 원본과 제외 사유를 보존한다.
- [ ] `data/metadata.csv`에 `file,class_id,signer,background,lighting,angle,scale`을 기록한다. `file`은 data 기준 상대 경로, signer는 익명 촬영자 ID다.
- [ ] 파일명 충돌을 피하고 파일·메타데이터의 일대일 대응과 클래스 번호를 확인한다.
- [ ] 동일·유사 촬영본을 그룹으로 묶고, 그룹을 나누지 않은 채 클래스·촬영자별 약 80:20 train/val로 배정한다. 시드 42, 양쪽 모두 14클래스를 확보한다. 그룹 보존에 따라 실제 비율은 달라질 수 있다.
- [ ] `data/split.csv`의 `file,partition,group_id`와 파일별 SHA256을 고정해 개인 모델 간 공유한다.

완료 기준: 원본·라벨·분할이 확인되고 집합 간 중복 그룹이 없다. 같은 촬영자를 공유하므로 검증 정확도를 새 사람에 대한 독립 성능으로 해석하지 않는다.

## 4. P02: 전처리와 Dataset

- [ ] 전체 RGB 이미지에서 긴 변을 128로 축소한다. 비율과 패딩 위치를 직접 계산해 검은 배경의 128×128에 배치한다.
- [ ] CHW 순서의 float32 텐서로 바꾸고 255로 나누어 0~1 범위로 만든다.
- [ ] 학습에만 회전 -10~10도, 배율 0.90~1.00, 밝기 0.90~1.10을 독립 균등 추출한다. 이미지가 잘리지 않도록 회전 후 크기·배율·패딩을 계산한다.
- [ ] 검증·추론에는 난수 증강을 적용하지 않는다. 좌우·상하 반전과 손 영역 자동 추출은 기준안에서 제외한다.
- [ ] 여러 자음의 전처리 전후를 확인해 손가락 보존·방향·색상·텐서 크기를 확인한다.

완료 기준: 같은 이미지의 검증용 입력과 추론용 입력이 동일하고, 증강된 이미지의 라벨 의미와 손 형태가 유지된다.

## 5. P03: 모델 전체 구조

- [ ] Conv2d(3×3, stride 1, padding 1) → BatchNorm2d → ReLU → MaxPool2d(2) 블록을 3개 구성한다.
- [ ] 채널은 3→16→32→64, 공간 크기는 128→64→32→16으로 한다.
- [ ] 분류부는 AdaptiveAvgPool2d(4×4) → Flatten(1024) → Linear(1024,64) → ReLU → Dropout(0.2) → Linear(64,14)로 한다.
- [ ] 손실은 CrossEntropyLoss, 정답은 int64 클래스 번호, 예측은 argmax(dim=1)로 한다. 손실 앞에 sigmoid·softmax를 붙이지 않는다.

완료 기준: 배치 크기가 달라도 14출력 로짓을 반환한다. 이 구조는 초기 비교 기준이며 최적 성능을 보장하지 않는다.

## 6. P04: 학습·증강 비교·기록

- [ ] Adam, 학습률 0.001, 배치 32, 조건별 30 epoch, 시드 42, num_workers=0으로 시작한다.
- [ ] 증강 off/on은 동일한 초기 state_dict를 복사해 시작하고, 데이터 섞기와 증강 난수를 분리해 배치 순서를 동일하게 유지한다.
- [ ] 모든 학습 배치를 처리한다. epoch마다 eval·no_grad로 증강 없는 전체 train/val을 다시 평가한다.
- [ ] 평균 손실은 배치 손실×실제 샘플 수의 합을 전체 수로 나누고, 정확도는 정답 수/전체 수로 기록한다.
- [ ] 검증 정확도 우선, 동률이면 낮은 검증 손실로 가중치를 고른다. 모두 같으면 먼저 저장한 것을 유지한다. 조건 간 완전 동률이면 off를 선택한다.
- [ ] 조건별 `train_log.csv` 열은 `epoch,train_loss,train_acc,val_loss,val_acc`, 정확도 단위는 0~1로 한다.
- [ ] `runs/실행ID/off/`, `on/`에 각 로그·가중치를 보존한다. `config.json`, 사용한 split.csv와 원본 해시 목록도 함께 보존한다.
- [ ] 메모리 부족이면 배치를 16 또는 8로 낮추고 두 조건 모두 같은 배치로 비교한다. 입력 해상도 변경은 별도 실험으로 다룬다.

완료 기준: 조건별 30개 epoch 기록과 최고 가중치가 존재하고, 초기 조건·분할·설정이 추적된다. 학습 정확도와 검증 정확도를 혼동하지 않는다.

## 7. P05: 평가와 결과 선택

- [ ] 최고 가중치를 다시 읽어 검증 전체의 혼동행렬을 직접 누적한다. 정답은 행, 예측은 열이다.
- [ ] 14×14 행렬 합=검증 수, 대각선 합/전체 합=검증 정확도를 확인한다.
- [ ] 두 방향 오분류 합이 가장 큰 자음 쌍과 건수를 기록한다.
- [ ] `selected/`에 best.pt, 선택 조건의 train_log.csv, confusion_matrix.png, comparison.csv를 보존한다.
- [ ] comparison.csv 열은 `augmentation,best_epoch,val_loss,val_acc`로 한다. best.pt에는 model_state, 입력 크기·라벨 순서·전처리 규칙·epoch·증강 여부·검증 지표를 함께 저장한다.

완료 기준: 선택 근거와 기록·가중치·혼동행렬이 일치한다. 시험 데이터로 설정이나 가중치를 선택하지 않는다.

## 8. P06: 추론과 제출

- [ ] 루트에서 `python src/predict.py --input test_images/ --output predict_팀번호.csv`로 원본 폴더를 처리한다. `src/`에서 과제 명령을 쓰면 루트 입출력은 `--input ../test_images/ --output ../predict_팀번호.csv`로 지정한다.
- [ ] 바로 아래 JPG/JPEG/PNG를 파일명 순으로 처리하며 확장자는 대소문자를 구분하지 않는다. 이미지가 있는 하위 폴더는 알려 배치를 확인하고 조용히 누락하지 않는다.
- [ ] 원본을 수정하지 않고 모든 이미지가 성공한 경우에만 CSV를 완성한다. 빈 폴더·읽기 실패·가중치 불일치는 원인과 함께 실패 종료한다. 기존 결과는 덮어쓰지 않는다.
- [ ] 제출물의 `src/`에 data_processing.py·model.py·train.py·predict.py를 함께 넣고 루트에 requirements.txt와 best.pt를 둔다. train.py·predict.py가 공통 데이터 처리를 가져오므로 네 파일 중 하나라도 누락하면 실행되지 않는다. 과제 명령은 제출물의 `src/`에서 실행한다.
- [ ] 팀 데이터 data.zip, best.pt, train_log.csv, 혼동행렬 이미지와 2분 이내 영상을 준비한다.
- [ ] 시험 이미지 수·실행 장치가 정해지면 읽기부터 CSV 저장까지 시간을 확인한다. 시험 결과 제출 제한은 30분이다.

완료 기준: 입력 파일당 정확히 한 행, pred는 정수 0~13이며, 새 환경에서 필요한 파일과 실제 사용 의존성 버전이 갖춰져 있다.

## 9. 현재 진행 상태

네 구현 파일은 `src/`에 작성했고 `requirements.txt`는 루트에 있다. 위 체크리스트의 완료 표시는 실제 팀 데이터 기준으로 남겨 두며, 합성 확인만으로 실제 데이터 단계의 완료를 표시하지 않는다.

`src/` 이동 후 루트와 `src/`에서 각각 실행한 학습 명령이 루트 `data/metadata.csv`를 찾는 것을 확인했다. 실제 데이터가 없어 검사 단계에서 중단했다. 임시 제출 구조와 합성 이미지에서는 양쪽 예측 명령이 루트 best.pt를 읽고 같은 CSV를 만들었다. 이번 경로 확인에서 새 학습은 수행하지 않았다.

- P01: 대기. `data/`에는 `.gitkeep`만 있고 실제 사진·metadata.csv·split.csv는 없다. 검사 코드는 작성했지만 촬영 품질·유사 그룹 확인과 공통 분할 확정은 남아 있다.
- P02: 구현했다. 합성 이미지의 크기·dtype·범위·결정적 전처리·증강 난수·EXIF 보정을 확인했다. 실제 사진에서 손가락 보존과 증강 적절성을 확인해야 한다.
- P03: 구현했다. 합성 입력의 배치 1·3에서 `[B,14]` 출력과 소규모 학습의 손실·가중치 재로딩을 확인했다.
- P04~P05: 증강 off/on, 전체 train/val 재평가, 로그·체크포인트, 선택 규칙, 혼동행렬과 비교 결과 저장을 구현했다. 합성 이미지의 조건별 2 epoch로 개별 흐름을 확인했다. 별도로 14클래스·420장의 합성 JPG에서 조건별 1 epoch로 데이터 검사부터 최종 결과 저장까지 확인했다. 실제 데이터의 조건별 30 epoch 실행과 성능 분석은 남아 있다.
- P06: 폴더 예측과 CSV 저장을 구현했다. 합성 이미지로 파일 순서·라벨 범위·기존 출력 보존·손상 및 하위 폴더 이미지의 실패 처리를 확인했다. 실제 가중치 예측·제출 묶음·영상·시험 시간 확인은 남아 있다.

확인 환경은 Windows, Python 3.12.13, PyTorch 2.13.0+cpu, NumPy 2.5.1, Pillow 12.3.0, matplotlib 3.11.1이다. 새 패키지는 설치하지 않았고 CUDA는 확인하지 않았다. 실제 데이터 수량, 팀 번호, 제출 기한, 시험 환경은 확인 후 반영한다.
