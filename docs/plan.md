# 수화 이미지 분류 상세 계획

갱신일 2026-11-20

## 1. 목표와 범위

팀원이 직접 촬영한 한글 지문자 자음 14종을 분류한다. 팀 전체가 원본 데이터와 비교용 분할을 공유하며, 최종 선정 코드와 결과는 팀원이 설명할 수 있어야 한다. 과제의 제출 기준은 [기말과제 공지](기말과제공지.pdf)를 따른다.

클래스 번호 0~13은 `ㄱ, ㄴ, ㄷ, ㄹ, ㅁ, ㅂ, ㅅ, ㅇ, ㅈ, ㅊ, ㅋ, ㅌ, ㅍ, ㅎ` 순서다. 원본 클래스 폴더는 `c00`~`c13`이다. 쌍자음과 모음은 제외한다. 직접 구성한 CNN을 팀 데이터로 처음부터 학습하며 사전학습 가중치와 손 검출·키포인트 모델을 사용하지 않는다.

## 2. 파일과 실행 경로

| 파일 | 역할 |
| --- | --- |
| `src/data_processing.py` | 원본 리사이즈, 학습·검증 분할, 분할표 저장, 공통 이미지 처리 함수 |
| `src/model.py` | CNN 구조, 가중치 저장 형식, 예측용 가중치 불러오기 |
| `src/train.py` | 데이터 로딩, 실시간 증강, 학습·검증 반복, 최종 결과 저장 |
| `src/predict.py` | 시험 원본의 전처리, 모델 예측, `filename,pred` CSV 저장 |

`requirements.txt`는 루트에 둔다. 원본은 `data/`, 학습 입력은 `data_prosessing/`, 결과는 `result/실행ID/`, 예측 가중치는 루트 `best.pt`를 사용한다. `train.py`와 `predict.py`가 공통 모듈을 불러오므로 제출 코드에는 네 파일을 함께 넣는다.

루트에서 `python src/train.py`, `src/`에서 `python train.py`로 학습을 시작한다. `data_prosessing/`이 없으면 학습 시작 전에 원본을 자동으로 전처리하고, 있으면 재사용한다. 원본 또는 분할을 바꾼 뒤에는 기존 전처리 폴더를 옮기고 다시 실행한다. 전처리만 따로 실행할 때는 루트에서 `python src/data_processing.py`를 사용한다.

## 3. P01 데이터 확인과 공통 분할

- [x] 현재 원본 420장이 `data/c00/`~`data/c13/`에 클래스당 30장씩 있다. 모두 4000×2252 JPG이며 바이트가 동일한 원본은 없었다.
- [x] `data/metadata.csv` 420행에 원본 상대 경로 `file`과 클래스 번호 `class_id`를 채웠다.
- [ ] 팀원 전원의 직접 촬영 여부와 팀원당 자음별 최소 30장, 총 최소 420장을 확인한다. 인터넷·공개 데이터와 다른 팀의 사진을 제외한다.
- [ ] 사진의 손·손목이 화면 대부분을 차지하는지, 배경 3종 이상, 조명 2종 이상, 다양한 각도와 화면 높이 약 3/4·1/2·1/3의 손 크기가 포함되는지 확인한다. 흐린 사진, 틀린 손 모양, 연사 복제 사진을 제외한다.
- [ ] `metadata.csv`에서 비어 있는 `signer,background,lighting,angle,scale`을 실제 촬영 정보로 채운다.
- [ ] 유사 촬영본에 그룹을 부여하고 팀 공통 `data/split.csv`를 확정한다. 열은 `file,partition,group_id`다. 한 그룹은 한쪽에만 배치하고 양쪽 모두 14개 자음을 포함한다.

현재 결과 폴더에는 시드 42로 자음별 약 80:20 분할을 적용했다. 학습 336장과 검증 84장이며 `data_prosessing/split.csv`에서 사진별 배정을 확인할 수 있다. 이 분할에는 촬영 그룹 정보가 없어 유사 사진이 양쪽에 있을 수 있다. 팀 비교에는 그룹을 반영한 공통 분할을 사용한다.

## 4. P02 전처리와 실시간 증강

- [x] 원본 저장 방향과 비율을 유지하며 긴 변을 128px로 맞춘다. 전처리된 현재 사진 420장은 모두 128×72이고, `train/c00`~`c13` 및 `val/c00`~`c13`에 저장한다.
- [x] 학습·검증·예측 입력은 RGB 사진을 검은 배경 가운데에 놓아 128×128로 맞춘다. Torchvision v2의 `ToImage()`와 `ToDtype(torch.float32, scale=True)`로 CHW, float32, 0~1 텐서를 만든다.
- [x] 증강을 켠 학습 사진을 꺼낼 때마다 회전 −10°~+10°와 밝기 0.9~1.1배를 적용한다. 회전 뒤 비율을 유지해 다시 크기를 맞춘다. 검증과 예측에는 공통 입력 변환만 적용한다.
- [ ] 팀 전체 사진에서 손 모양이 충분히 보이고 증강 뒤 라벨 의미가 유지되는지 확인한다.

## 5. P03 모델 구조

- [x] Conv2d → BatchNorm2d → ReLU → MaxPool2d 블록을 세 번 사용한다. 채널은 3→16→32→64, 공간 크기는 128→64→32→16으로 줄어든다.
- [x] AdaptiveAvgPool2d(4×4) → Flatten → Linear(1024,64) → ReLU → Dropout(0.2) → Linear(64,14)로 14개 점수를 낸다.
- [x] 입력은 `[B,3,128,128]`, 출력은 `[B,14]`다. 학습 손실에 CrossEntropyLoss를 쓰고 예측 번호는 `argmax(dim=1)`으로 고른다.

## 6. P04 학습·증강 비교·기록

- [x] Adam 0.001, 배치 32, 조건별 30 epoch, 시드 42를 기본값으로 둔다. `--augmentation`은 `off`, `on`, `both`를 받으며 기본값은 `both`다.
- [x] 증강 끔·켬은 모델 초기화와 학습 데이터 순서에 같은 시드를 사용한다. 매 epoch `train_epoch()`는 실제 학습 배치의 지표를, `evaluate_model()`은 증강 없는 검증 배치의 지표를 계산한다.
- [x] 조건별 `off/`, `on/`에 `train_log.csv`와 `best.pt`를 저장한다. 로그 열은 `epoch,train_loss,train_acc,val_loss,val_acc`이며 정확도 범위는 0~1이다. 손실은 배치별 실제 사진 수로 가중해 평균을 낸다.
- [x] 검증 정확도가 높을수록 우선하고, 동률이면 검증 손실이 낮은 가중치를 고른다. 두 지표가 같으면 먼저 나온 기록을 유지한다.
- [ ] 팀 전체 원본과 공통 분할이 확정되면 조건별 30 epoch 본학습과 성능 비교를 수행한다.

## 7. P05 최종 평가와 결과 선택

- [x] `result()`는 선택한 최고 가중치를 다시 불러와 검증 전체의 14×14 혼동행렬을 계산한다. 행은 정답, 열은 예측이며 양방향 오분류를 합산해 가장 많이 혼동한 자음 쌍을 출력한다.
- [x] `selected/`에 최종 `best.pt`, `train_log.csv`, `confusion_matrix.png`를 저장한다. 두 조건을 실행하면 `comparison.csv`에 `augmentation,best_epoch,val_loss,val_acc`를 저장한다.
- [x] 현재 데이터의 학습 336장·검증 84장으로 증강 켬·끔 각 1 epoch를 확인했다. 혼동행렬 합계는 84장이었고 대각선 합으로 계산한 정확도가 검증 정확도와 일치했다.
- [ ] 본학습 결과의 최고 가중치·로그·비교표·혼동행렬을 확인하고 제출용으로 선별한다.

## 9. 현재 확인 범위

Windows의 `nail` 환경에서 Python 3.12.16, PyTorch 2.13.0+cpu, Torchvision 0.28.0+cpu로 확인했다. 1 epoch 결과는 실행 흐름 검증에 사용했고, 현재 작업 폴더에는 본학습 가중치·결과·제출 ZIP이 없다. 팀 번호, 제출 기한, 시험 입력 규모와 장치는 확인이 필요하다.
